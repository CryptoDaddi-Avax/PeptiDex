# Internal Linking Strategy — PeptiDex

This document defines the deterministic rules governing internal linking across peptidex.app. All rules are implemented in code — no manual link maintenance required.

---

## 1. Breadcrumbs

### Component
`src/components/breadcrumbs.tsx` — renders both the visible `<nav>` trail and a `BreadcrumbList` JSON-LD schema in a single `<script>` tag.

### Coverage

| Route pattern | Breadcrumb trail | Implementation |
|---|---|---|
| `/peptides/[slug]` | Home → Peptide Library → {Category} → {Peptide} | Hard-coded in page.tsx |
| `/library/[slug]` | PeptiDex → Library → {Peptide} | JSON-LD in server component; visual in client |
| `/stacks/[slug]` | Home → Stacks → {Stack Name} | JSON-LD + visual `<nav>` in page.tsx |
| `/vendors/[slug]` | Home → Vendors → {Vendor} | Inline `<nav>` + JSON-LD in page.tsx |
| `/tools/*` | Home → Tools → {Tool Name} | Auto-generated by `ToolsBreadcrumbs` in tools layout |
| `/blog/[slug]` | Home → Blog → {Title} | Varies by page |

### Tool Name Resolution (`ToolsBreadcrumbs`)
`src/components/tools/ToolsBreadcrumbs.tsx` reads `usePathname()` and resolves slug → display name via a static lookup table. Falls back to title-cased slug. Rendered via `src/app/tools/layout.tsx` — zero per-page configuration needed.

## 2. Related Content Blocks

### Peptide Profile Pages (`/peptides/[slug]`, `/library/[slug]`)

**Related Research Profiles** (`RelatedPeptides` component):
- Logic: peptides that share a **synergy relationship** (appear in `interactions.synergies`) OR share the same **category** as the current peptide.
- Sorted by: synergy first, then category, then alphabetical.
- Count: top 3 shown.

**Stacks containing {peptide}**:
- Logic: `stacks.filter(s => s.peptides.some(p => p.name includes peptide.name))`.
- All matching stacks shown (typically 0–3).

### Stack Pages (`/stacks/[slug]`)

**Explore Other Goal Stacks**:
- Shows all stacks except current, sorted by array order in `stacks.ts`.

### Vendor Review Pages (`/vendors/[slug]`)

**Compare to Other Vendors** (`VendorCompare` component):
`src/components/vendors/VendorCompare.tsx`
- Logic: filter out current vendor, sort remaining by `overallRating` descending, take top 3.
- Fully deterministic — highest-rated vendors surface first.

**Related: {Vendor}** (subPages):
- Links to the vendor's own FAQ, discount code, and comparison sub-pages as defined in `src/data/reviews/*.ts` → `subPages[]`.

## 3. Contextual Prose Linking (AutoLink)

### Implementation
`src/components/auto-link.tsx` — `AutoLinkProvider` + `AutoLink` components.

**Rules enforced:**
1. **First mention only** — each peptide slug is tracked via `AutoLinkContext` (a `Set<string>`). Only the first occurrence of each name is linked per page.
2. **Skips headings** — `h1`, `h2`, `h3`, `h4` are never auto-linked.
3. **Skips existing links** — `<a>` and Next.js `<Link>` elements pass through unchanged.
4. **Skips code blocks** — `<code>` and `<pre>` are not processed.
5. **Longest match first** — the dictionary is sorted by term length descending to prevent partial matches (e.g., "CJC-1295 DAC" before "CJC-1295").
6. **Alias support** — all peptide `aliases[]` are matched in addition to the canonical name.
7. **Link target** — always `/library/[slug]` (canonical library URL).

### Where AutoLink is active

| Route | Status |
|---|---|
| `/peptides/[slug]` | ✅ wraps full article body |
| `/library/[slug]` | Client component handles internally |
| `/stacks/[slug]` | ✅ wraps goal description + synergy rationale |
| `/blog/[slug]` | ✅ dynamic blog pages |
| `/blog/*` | ✅ all static blog posts |
| `/learn/[slug]` | ✅ learn article body |
| `/vendors/amino-club/*` sub-pages | ✅ |
| `/compare/*` | ✅ |
| Vendor review pages (`/vendors/[slug]`) | ❌ not wrapped (short-form review content) |

## 4. Homepage Brand Link

The homepage does not inject `"PeptiDex"` links into body copy. The brand appears in the site `<title>`, `og:title`, and schema.org `Organization` name — sufficient for Google's brand association. No footer link stuffing.

---

## 5. Anchor Text Conventions

| Context | Rule |
|---|---|
| AutoLink (prose) | Use exact peptide name as anchor text (preserves original casing) |
| Related content cards | Use peptide/stack/vendor display name |
| Compare block | Use vendor name |
| Breadcrumbs | Use page title (truncated to fit) |

**Prohibited**: "click here", "learn more", "this page", "here" as standalone anchor text.

---

## 6. Adding New Peptides

When a new peptide is added to `src/data/peptides.ts`:
1. AutoLink picks it up automatically (DICTIONARY is built from `peptides` at module init time).
2. RelatedPeptides picks it up automatically (sorted from the live array).
3. Breadcrumbs require no update — slug is derived from route.
4. Sitemap requires no update — `generateStaticParams()` covers all peptides.
